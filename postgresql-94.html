    11.1.2. Geração dos bancos de dados

    A partir de agora, a conexão com os bancos de dados PostgresSQL será feita com as credenciais [postgres / postgres]. Execute o PostgreSQL e seu cliente [PgManager] (consulte o parágrafo 23.7).

    • no [1], será carregado o script SQL [<exemples>\spring-database-config\postgresql\databases\dbproduits.sql];
    • no [2]; assim como no Oracle, as camadas JPA utilizam sequências para gerar as chaves primárias. Aqui, a sequência [produits_sequence] gera as chaves primárias da tabela [produits];

    Agora, execute as configurações:

    • [spring-jdbc-generic-01.IntroJdbc01];
    • [spring-jdbc-generic-01.IntroJdbc02];
    • [spring-jdbc-generic-03.JUnitTestDao1];

    Todas devem ser bem-sucedidas.

    Vamos agora gerar a base [dbproduitscategories]. Repita para [dbproduitscategories] o procedimento realizado para criar [dbproduits]. O script SQL a ser carregado está localizado em [<exemples>\spring-database-config\postgresql\databases\ dbproduitscategories.sql];

      

    Agora, execute as configurações:

    11.2. Configuração da camada JDBC

     

    O projeto [postgresql-config-jdbc] configura a camada [JDBC] da seguinte arquitetura de testes:

    O projeto é análogo ao projeto de configuração [mysql-config-jdbc] da camada JDBC do SGBD MySQL (ver parágrafo 3.3). Apresentamos apenas as alterações:

    </parent>

        </dependency>        
      <!-- dependências constantes ********************************************** -->
        ...
    </dependencies>

    • linhas 18-22: o driver JDBC a partir de PostgreSQL;

    A segunda modificação está na classe [ConfigJdbc], que define os identificadores de acesso aos bancos de dados:

    
    // parâmetros de conexão
    public final static String DRIVER_CLASSNAME = "org.postgresql.Driver";
    public final static String URL_DBPRODUITS = "jdbc:postgresql:dbproduits";
    public final static String USER_DBPRODUITS = "postgres";
    public final static String PASSWD_DBPRODUITS = "postgres";
    public final static String URL_DBPRODUITSCATEGORIES = "jdbc:postgresql:dbproduitscategories";
    public final static String USER_DBPRODUITSCATEGORIES = "postgres";
public final static String PASSWD_DBPRODUITSCATEGORIES = "postgres";

    A terceira modificação que pode ser feita é a do número máximo de parâmetros que um [PreparedStatement] pode suportar:

    
    // número máximo de parâmetros de um [PreparedStatement]
    public final static int MAX_PREPAREDSTATEMENT_PARAMETERS = 10000;

    O teste [JUnitTestPushTheLimits] gera ordens SQL para 5.000 produtos, que, por sua vez, gerarão [PreparedStatement] com 5.000 parâmetros. O MySQL já havia suportado esse valor. O PostgreSQL também.

    A quarta modificação é mais surpreendente:

    
public final static String TAB_PRODUITS_ID = "id";
public final static String TAB_CATEGORIES_ID = "id";

    Os nomes das colunas [ID] das tabelas [CATEGORIES] e [PRODUITS] devem estar em letras minúsculas para o projeto [spring-jdbc-04]. Caso contrário, ocorre uma falha nas instruções que utilizam os dois beans a seguir deste projeto:

    
    // inserção de produto
    @Bean
    public SimpleJdbcInsert simpleJdbcInsertProduit(DataSource dataSource) {
        return new SimpleJdbcInsert(dataSource)
                .withTableName(ConfigJdbc.TAB_PRODUITS)
                .usingGeneratedKeyColumns(ConfigJdbc.TAB_PRODUITS_ID)
                .usingColumns(ConfigJdbc.TAB_PRODUITS_NOM, ConfigJdbc.TAB_PRODUITS_PRIX, ConfigJdbc.TAB_PRODUITS_DESCRIPTION,
                        ConfigJdbc.TAB_PRODUITS_CATEGORIE_ID);
    }

    // adição de categoria
    @Bean
    public SimpleJdbcInsert simpleJdbcInsertCategorie(DataSource dataSource) {
        return new SimpleJdbcInsert(dataSource).withTableName(ConfigJdbc.TAB_CATEGORIES)
                .usingGeneratedKeyColumns(ConfigJdbc.TAB_CATEGORIES_ID)
                .usingColumns(ConfigJdbc.TAB_CATEGORIES_NOM);
}

    11.3. Configuração da camada JPA OpenJpa

     

    O projeto [postgresql-config-jpa-openjpa] configura a camada [JPA] da arquitetura de testes:

    O projeto é análogo ao projeto de configuração [oracle-config-jpa-openjpa] da camada JPA OpenJpa do SGBD Oracle (ver parágrafo 10.5). De fato, os dois SGBD utilizam sequências para gerar as chaves primárias. Há apenas uma modificação a ser feita. Ela está na definição do bean [jpaVendorAdapter] da classe [ConfigJpa]:

    
    // o provedor JPA
    @Bean
    public JpaVendorAdapter jpaVendorAdapter() {
        OpenJpaVendorAdapter openJpaVendorAdapter = new OpenJpaVendorAdapter();
        openJpaVendorAdapter.setShowSql(false);
        openJpaVendorAdapter.setDatabase(Database.POSTGRESQL);
        openJpaVendorAdapter.setGenerateDdl(true);
        return openJpaVendorAdapter;
}
    • linha 6: indica-se à implementação JPA que ela trabalhará com um banco de dados PostgreSQL. A implementação JPA adotará, então, tanto os tipos de dados proprietários quanto o SQL, que é o proprietário desse SGBD.

    Após essas alterações, a execução da configuração [spring-jpa-generic-JUnitTestDao-openjpa] deve ser bem-sucedida.
