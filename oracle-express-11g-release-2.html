    10.1.3. Instalação do driver JDBC da Oracle no repositório Maven

    O driver JDBC da Oracle não está disponível nos repositórios centrais do Maven. É necessário baixá-lo do site da Oracle [http://www.oracle.com/technetwork/apps-tech/jdbc-112010-090769.html]:

    Após o download, é necessário instalá-lo no repositório local do Maven. Isso é feito com o seguinte script:

    "%M2_HOME%\bin\mvn.bat" install:install-file -Dfile=ojdbc6.jar -Dpackaging=jar -DgroupId=com.oracle.jdbc -DartifactId=ojdbc6 -Dversion=1.0

    onde se substituirá [%M2_HOME%] pelo caminho do diretório de instalação do Maven (ver parágrafo 23.2). Feito isso, o driver JDBC poderá então ser importado para os projetos Maven por meio da configuração:

    
        <dependency>
            <groupId>com.oracle.jdbc</groupId>
            <artifactId>ojdbc6</artifactId>
            <version>1.0</version>
</dependency>

    • linhas 18-19: a estratégia de geração da chave primária da tabela [PRODUITS] é [strategy=GenerationType.SEQUENCE]. Para MySQL, havia sido utilizada a estratégia [@GeneratedValue(strategy = GenerationType.IDENTITY)]. Com o Oracle Express 11g, essa estratégia não pode ser utilizada;
    • linha 18: indica-se que a chave primária será obtida por meio de um gerador de números, frequentemente chamado de sequência;
    • linha 19: o gerador de sequências (o atributo name faz referência ao gerador da linha 18) criará uma sequência chamada [PRODUITS_SEQUENCE] no banco de dados [dbproduits]. Como se deseja garantir a portabilidade entre as implementações JPA, é importante nomear a sequência. Caso contrário, na ausência da linha 19, as três implementações JPA criarão sequências que não terão o mesmo nome, tornando impossível a utilização, por JPA2, de um banco de dados criado por JPA1;

    • uma tabela [PRODUITS];
    • uma sequência chamada [PRODUITS_SEQUENCE]

    O DDL da tabela [PRODUITS] é o seguinte:

     

    A chave primária [ID] não é autoincrementada, como era o caso com MySQL. No entanto, o projeto [spring-jdbc-03] pressupõe que o SGBD se encarrega de gerar as chaves primárias da tabela [PRODUITS]. Vamos criar um trigger ou um déclencheur. Um trigger é um procedimento armazenado dentro do SGBD que é executado sob determinadas condições. Vamos criar um trigger que, a cada nova inserção, gere a chave primária do produto inserido a partir da sequência [PRODUITS_SEQUENCE] criada pela configuração JPA.

    • em [6], o trigger [PRODUITS_ID_TRIGGER] [4] será executado antes de cada inserção;
    • em [7], um procedimento armazenado específico do SGBD do Oracle. Ela indica que o campo [ID] da linha que será inserida deve ser inicializado com o seguinte valor do gerador denominado [PRODUITS_SEQUENCE];

    Assim como foi feito para a base [dbproduits], serão geradas cinco sequências. Elas são utilizadas pelas implementações JPA para gerar as chaves primárias. As implementações JPA não utilizam triggers, como fizemos anteriormente, mas consultam as sequências para obter a próxima chave primária. Nós, por outro lado, geraremos as chaves primárias também com triggers. Estes são necessários para o projeto [spring-jdbc-04].

    10.3. Configuração da camada JPA EclipseLink

     

    Observação: execute o [Alt-F5] para regenerar todos os projetos Maven.

    O projeto [oracle-config-jpa-eclipseLink] configura a camada [JPA] da arquitetura de testes:

    O projeto é análogo ao projeto de configuração [mysql-config-jpa-eclipselink] (ver parágrafo 7.3) da camada JPA Eclipselink do SGBD MySQL. Apresentamos apenas as alterações:

    A primeira está na classe [ConfigJpa], na definição do bean [jpaVendorAdapter]:

    
    // o provedor JPA
    @Bean
    public JpaVendorAdapter jpaVendorAdapter() {
        // Observação: as entidades JPA e a configuração do EclipseLink estão no arquivo META-INF/persistence.xml
        EclipseLinkJpaVendorAdapter eclipseLinkJpaVendorAdapter = new EclipseLinkJpaVendorAdapter();
        eclipseLinkJpaVendorAdapter.setShowSql(false);
        eclipseLinkJpaVendorAdapter.setDatabase(Database.ORACLE);
        eclipseLinkJpaVendorAdapter.setGenerateDdl(true);
        return eclipseLinkJpaVendorAdapter;
}
    • linha 7: indica-se à implementação JPA que ela trabalhará com um banco de dados Oracle. A implementação JPA adotará, então, tanto os tipos de dados proprietários quanto o SQL, que é proprietário da Oracle.

    A segunda modificação diz respeito à estratégia de geração de chaves primárias. A nova estratégia foi apresentada no parágrafo 10.1.
