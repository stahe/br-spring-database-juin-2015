    12.1.2. Geração dos bancos de dados

    Assim como foi feito com o Oracle, precisaremos instalar o driver JDBC do DB2 no repositório local do Maven.

      

    O arquivo [install.bat] contém o seguinte código:

    "%M2_HOME%\bin\mvn.bat" install:install-file -Dfile=db2jcc4.jar -Dpackaging=jar -DgroupId=com.ibm.jdbc -DartifactId=db2jcc4 -Dversion=1.0

    onde [%M2-HOME%] é a pasta de instalação do Maven (ver parágrafo 23.2). Após essa instalação, o driver JDBC do DB2 pode ser referenciado nos arquivos [pom.xml] por meio da seguinte dependência:

    
        <dependency>
            <groupId>com.ibm.jdbc</groupId>
            <artifactId>db2jcc4</artifactId>
            <version>1.0</version>
</dependency>

    Daqui em diante, a conexão com os bancos de dados DB2 será feita com os credenciais [db2admin / db2admin]. Inicie o DB2 e seu cliente [Db2Manager] (ver parágrafo 23.8).

    A terceira alteração que pode ser feita é a do número máximo de parâmetros que um [PreparedStatement] pode suportar:

    
    // número máximo de parâmetros de um [PreparedStatement]
    public final static int MAX_PREPAREDSTATEMENT_PARAMETERS = 10000;

    O teste [JUnitTestPushTheLimits] gera ordens SQL para 5.000 produtos, que, por sua vez, gerarão [PreparedStatement] com 5.000 parâmetros. O MySQL já suportava esse valor. O DB2 também.

    A quarta modificação diz respeito ao nome da tabela [ROLES]. Na verdade, esse nome já está reservado nas tabelas SGBD e DB2. Por isso, renomeamos a tabela para [ROLES_]:

    
public final static String TAB_ROLES = "ROLES_";
public static final String SELECT_ROLES_BYUSERID = "SELECT DISTINCT r.ID as r_ID, r.VERSIONING as r_VERSIONING, r.NAME as r_NAME FROM ROLES_ r, users u, USERS_ROLES ur"
+ " WHERE u.ID=:id AND ur.USER_ID=u.ID AND ur.ROLE_ID=r.ID";

    12.3. Configuração da camada JPA OpenJpa

     

    O projeto [db2-config-jpa-openjpa] configura a camada [JPA] da arquitetura de testes:

    O projeto é análogo ao projeto de configuração [mysql-config-jpa-openjpa] da camada JPA OpenJpa do SGBD MySQL (ver parágrafo 8.3). De fato, os dois SGBD utilizam a anotação [@GeneratedValue(strategy = GenerationType.IDENTITY)] para gerar as chaves primárias. Há apenas uma alteração a ser feita. Ela está na definição do bean [jpaVendorAdapter] da classe [ConfigJpa]:

    
    // o provedor JPA
    @Bean
    public JpaVendorAdapter jpaVendorAdapter() {
        OpenJpaVendorAdapter openJpaVendorAdapter = new OpenJpaVendorAdapter();
        openJpaVendorAdapter.setShowSql(false);
        openJpaVendorAdapter.setDatabase(Database.DB2);
        openJpaVendorAdapter.setGenerateDdl(true);
        return openJpaVendorAdapter;
}
    • linha 6: indica-se à implementação JPA que ela trabalhará com um banco de dados DB2. A implementação JPA adotará, então, tanto os tipos de dados proprietários quanto o SQL, que é o proprietário desse SGBD.

    Após essas alterações, a execução da configuração [spring-jpa-generic-JUnitTestDao-openjpa] deve ser bem-sucedida.
